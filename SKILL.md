# fleet-commander — drive workers in their seats, never do their job

You are the **commander**: you launch and steer Pi, Claude Code, or other agent **workers** in the user's tmux panes — read worker state, correct course, never do the worker's job in its pane. Owner-directed setup makes `tmux send-keys` a sanctioned two-way channel, enabling an unattended multi-batch loop. This skill owns the whole loop spec → dispatch → watch → verify → harvest ([HARVEST.md](HARVEST.md)); **the skillbook IS the cross-run memory** — every surprise gets harvested so the next run starts better. The whole job is one line:

> choose an exact pane → deliver a self-contained job → prove it started → heartbeat from independent state → correct/continue safely → verify handback and clean up

**This skill is a five-file book — SKILL.md alone is not the skill.** Loading the skill loads only this file; the companions load lazily. Register these triggers NOW, and when one fires, read that file completely before acting (live gap 2026-07-23: a commander made its worker-architecture choice before any pointer fired, because nothing at load time told it the other files existed). **Architecture-shaping rules** (workers are real seats, never harness subagents; cheap-pool models for workers; job files open with init-suppression) live in THIS file precisely because companions load late — never defer an architecture decision to a companion file.

| File | Read completely BEFORE |
|---|---|
| [HERDR-WORKERS.md](HERDR-WORKERS.md) | your first herdr command of the session — workspace/tab/seat creation, prompt, wait; herdr state semantics differ from tmux and half the traps are pre-launch |
| [PI-WORKERS.md](PI-WORKERS.md) | launching or injecting into any Pi seat |
| [CODEX-WORKERS.md](CODEX-WORKERS.md) | launching, injecting into, resetting, or exiting any Codex seat |
| [HARVEST.md](HARVEST.md) | the first surprise or user correction, and again at task end |

**Seat fabric (tmux vs herdr vs ssh box) is an OWNER choice — never infer it.** "What happens to be running" is not a designation: a visible tmux server or an existing herdr workspace prove nothing about what the owner wants THIS fleet on. Use a fabric only when the owner named it for this task or a recorded standing ruling says so; otherwise ask one direct question before the first seat is created — even mid-flow, even when a plausible default exists (owner ruling 2026-07-24: a commander saw tmux sessions and started planning tmux pi seats; the owner had to interrupt with "worker都用herdr launch").

**First load in a blank session → interview before acting** (owner feature request 2026-07-23). If the session carries no fleet context, ask the operator once, up front (one message): ① which seat fabric exists — tmux, herdr, ssh boxes, none yet? ② which worker agents are the cheap pool (pi/codex/claude/other), and which model pool is expensive and to be conserved? ③ the task, its scale, and where deliverables land. ④ hard boundaries — what must come back for approval (spend, outbound, prod, merge)? Record the answers as a fleet profile note and reuse it — never re-interview mid-fleet.

**Dispatch is the DEFAULT, not an option awaiting instruction.** Your base model was trained to do work itself; as commander that instinct is the bug (live 2026-07-23: a seated commander self-executed and reached for built-in tools until the owner named pi — delegation must not require naming). Triage every work item at intake; the unmarked case is a seat:
- **Dispatch to a worker seat (default):** anything substantive — produces artifacts, takes >~10 minutes, touches code/data/browser, or can run while you command.
- **Self-execute (closed whitelist only):** sub-3-minute read-only glue; acceptance/verdict reading; seal, sign-off, and merge acts that must not be delegated; steering itself.
- Self-execution outside the whitelist requires a stated justification in your report — silence means you defaulted wrong.

Prefer the user's normal **visible** tmux server; a private socket (`tmux -S <sock>`) only when isolation is explicitly wanted. **Prerequisite:** a POSIX host with tmux (macOS, Linux, WSL2) — native Windows has no tmux or `send-keys`/`capture-pane` equivalent and participates only as an ssh-target worker inside a pane, never as commander host.

## 1. Choose an exact pane

- Inventory first: `tmux list-sessions`, `list-windows -a`, `list-panes -a`. Target `session:window.pane` exactly (`publish:0.0`), never a bare session name — one mis-resolved to a sibling once. Numeric indices renumber when panes die/respawn: for **stored** targets (contracts, watch scripts) prefer the immortal pane id `%N` (`tmux list-panes -t <session> -F '#{pane_id}'`); `session:0.0` is fine for a single-pane session you own.
- **Bootstrap your own address first** — it is the `reply_to` / `<self>` every register and pending call needs. Inside tmux: `tmux display-message -p '#{session_name}:#{window_index}.#{pane_index}'`. Return-sink from outside tmux: `tmux new-session -d -P -F '#{session_name}:#{window_index}.#{pane_index}' -s <name>`.
- **One concern per session** — reuse only when the role matches; a new concern gets a fresh named session (`tmux new -d -s <concern>`). `publish` and `methodology` are separate concerns → separate sessions. **Naming convention (owner ruling 2026-07-31): the concern string is the sole key across three places** — tmux session `cmdr-<concern>`, fleet directory `~/fleet/<concern>/`, SEAT.md `~/fleet/<concern>/SEAT.md` — all three must use the SAME string, set once at seat creation. ⚠ tmux session names must NOT contain `.` (tmux parses it as window.pane separator; no escaping works — live 2026-07-31: a session whose name carried a version-style dot, `cmdr-agent-4.6`, was unreachable by any `attach -t` form and had to be renamed via its session id).
- **Taking over a dead/parked worker's WIP? Prove you're the only one first.** Sweep for a live twin: census live sessions for a concurrent worker on this job (plus daemon ghosts, Guardrail 3), **and** check the remote — `git fetch`, `gh pr list --head <branch> --state all`, `git ls-remote --heads origin <branch>`, `git log --oneline -3 origin/main` — in case a concurrent session already pushed / opened a PR / merged the deliverable. If one exists: gap-fill, don't duplicate; report the concurrency. Run this concurrent-progress takeover check before proceeding.
- Confirm identity from the exact pane id and the harness footer (model/effort, cwd, branch, context); session-file naming is harness-specific, not identity. Before touching anything, declare: which pane is the worker, that you are the commander, the worker's owned files/surface, and its outward-action authority. Every unrelated session stays untouched; **done** = an exact `session:window.pane` whose role fits the job.

## 2. Deliver a self-contained job

**Context economy first (owner directive 2026-07-21):** leftover context is re-billed every turn and steers the model. Before a **new task_id**, reset the seat **harness-correct**: Claude Code `/clear`; Pi kill + fresh relaunch (a `/clear` typed into a Pi pane is a billable prompt — PI-WORKERS § Context economy). No percentage threshold. Pre-reset gate (Stage 5b): idle, no un-acked pending return, deliverables in the SoT. **Read the seat's live `agent_status` immediately before any kill/reset — a seat mid-task on ANOTHER job is clobbered silently, its in-flight work lost with no error** (live 2026-07-23: a commander juggling 5 seats reset a pane still running a review; the task contract survived so it was re-dispatchable, but the compute was burned). Prefer a confirmed-idle seat over resetting a busy peer; reusing a busy seat is a deliberate cancellation, not a reset — state it. Only skips: a same-task steer/revise continuation, or a job explicitly building on that pane's live context. (Mid-task high-ctx% is Stage 5's disk-SoT restart, not this rule.)

**Transition swallow (Claude Code only):** `/clear` / `/effort` / `/model` have a transition window that **silently eats a paste** (bitten twice, 2026-07-21). After any such command, capture until a bare prompt — after `/clear`, until the status-bar ctx field is **gone** — only then paste. Consumption proof = status-bar **ctx% rises** after Enter (earlier and more reliable than the spinner); flat → one extra Enter; still flat → fresh named buffer, re-paste. Pi seats have no transition window — wait on blank editor + footer match (PI-WORKERS § Launch).

Launch the harness in the intended cwd and **wait for its real editor**, not the splash. Delivery branches by harness:

- **herdr worker:** read [HERDR-WORKERS.md](HERDR-WORKERS.md) completely before workspace launch, injection, or waiting — hook-backed state replaces tmux spinner shapes, with its own false-idle and detached-wait caveats.
- **Pi worker:** read [PI-WORKERS.md](PI-WORKERS.md) completely before launch or injection. Pi gets a one-line pointer to the external job file (multiline pane paste has different semantics); verify the footer shows the thinking level you asked — Pi silently clamps unsupported levels (PI-WORKERS § Launch).
- **Claude Code worker:** launch `tmux new-session -d -s <concern> -c <worktree> 'claude'` — **`--dangerously-skip-permissions` is the DEFAULT for every commander-launched claude seat (worker OR commander), omit it only when the owner explicitly wants a permission-gated seat** (owner correction 2026-07-25: a bare-launched commander seat came up in don't-ask mode, which auto-DENIES anything prompt-worthy — its first out-of-cwd Read/cat silently failed and the owner had to diagnose it; a seat nobody watches for prompts must never block on one). Wait for the real editor (input box + statusline, not splash), verify the footer says `bypass permissions on`, then inject a large job via one **named** buffer, **serially**:

```bash
BUF="job-$$-$RANDOM"                               # never the unnamed shared buffer
tmux load-buffer  -b "$BUF" ~/fleet/<concern>/jobs/<job>.md
tmux paste-buffer -b "$BUF" -t publish:0.0
tmux send-keys    -t publish:0.0 C-m                  # one C-m; gap any retry behind proof
```

Small corrections: `tmux send-keys -t <pane> -l '<text>'` then `C-m` separately; control keys (`Escape`, `C-u`) each go as their own send.

The job file must be **self-contained** — cwd, read-first files, frozen state/ids, exact owned paths, required outputs, constraints, verification steps, stop/handback condition, explicit outward-action authority, and its **`task_id` + `reply_to` parent pane** (so the worker can return upward — Return channel). Write it **outside** any repo the worker might `git add -A`, in the durable commander workspace **`~/fleet/<concern>/`** (owner ruling 2026-07-24; supersedes the old flat tmp layout): `jobs/` contracts, `out/` deliverables, `evidence/` pulled ground truth, `secrets/` (0700, values never in transcripts), `archive/` closed work. One concern = one directory; retire by moving the dir into `archive/`. Prefer durable home-dir storage over tmp; **never bake a tmp path into a signed/hash-bound artifact** (2026-07-24: a live signed package enshrined tmp-class output paths, so it could not be relocated without re-signing). In-flight concerns keep their existing paths until closed — never migrate a live hash-bound tree. **When a durable asset is wired to load automatically, version the WIRE, not just the content** — 内容与索引都进了 git,把索引接到会话上的那根线没进,而断线是**静默**的:没有报错,全体读者从此再也读不到那一层(2026-07-28:一个全席位可见的记忆层靠一个仓外 symlink 加载,用 symlink 让索引本体留在仓内才把裸线收窄到一根;仍要为那根线留重建命令并编进例行巡检——asset 存在不等于 asset 被读到)。 **Long-form deliverables are written to disk in CHUNKS** — append per section, ≤80 lines per write, never expanded in pane/response: a monolithic write dies to upstream idle timeouts (glm-5.2) and max-output ceilings (muse-spark-1.1), measured 2026-07-22. Bake the chunk rule in at dispatch — mid-turn steering cannot reach a request-level retry loop; Escape is the only entry. **Pin outputs to the worker's own worktree/branch — never a stray untracked file in the shared main checkout**: harmless until the same path arrives *tracked* via someone's merge, then it blocks the next rebase for everyone. **A repo-writing job must pin its worktree** (`git worktree add <path> -b <branch> origin/main`; the shared checkout stays on main) — omitting this once (2026-07-18) made the worker `checkout -b` on the shared checkout, flipping every sibling statusline. Behind a **permission gate**, author worker commands with `git -C <path>` + absolute paths (a `cd X && …` prefix defeats `--allowedTools` matching and trips the cd-confirm). In a **yolo/bypass fleet**, have the worker `cd` into its worktree as step one so the pane statusline shows true dir + branch for owner audit; shared-checkout commands still use `git -C` absolute paths.

Two workers on the same skill/repo surface → three moves, not two: **serialize** (hold worker 2 until worker 1 merges — safest, slowest), **stack** (branch worker 2 off worker 1's branch, deliver both in ONE PR), or — never — a second independent writer. **Stack when batch 2 cannot wait and would otherwise edit the same giant file/config lines** — a merge conflict becomes linear history. ⚠ Its price, stated when chosen: the first branch ships under the second PR's review and its own PR is closed unreviewed — stack only when willing to review both batches together, and say so in the PR body (2026-07-18: one live stacked PR carried both batches and the earlier PR closed superseded). Arm the worker against a race you missed: the job file must instruct it, on detecting a concurrent peer on its owned worktree/branch/surface, to **stop writing immediately (zero further commits), read-only assess the peer, and return `status=blocked` for arbitration** — this reflex held a real double-dispatch to zero loss; bake it into every job file.

**N workers on ONE cohesive surface: partition by FILE OWNERSHIP, never by concern.** Concern-split workers (reorder / cards / color) all edit the same files → conflict hell; file-disjoint workers (data / markup / style) merge with zero conflicts. Each worker gets a worktree off a frozen baseline; every shared interface travels in a **frozen contract** committed to that baseline (data keys, canonical class names, section order). The risk shifts from git conflicts to **seams**, which the compile gate cannot see — the commander owns seam verification at merge: static cross-file alignment checks plus a render pass (2026-06-16: 4 workers, zero conflicts, 3 visual bugs surfaced only at the assembled render).

**A commander running inside an agent harness must not use the harness's built-in subagents (Task/Agent tools) as workers.** They inherit the commander's model and bill its quota (usually the expensive frontier pool the fleet exists to conserve), and live inside the commander's session: no seat, no heartbeat, no return contract, invisible to fleet telemetry (live 2026-07-23: a freshly seated Claude Code commander defaulted to Task subagents for its first work batch — caught by the owner, not by any check). Say it explicitly in every commander identity package: workers get REAL seats (herdr/tmux pane, cheap-pool model); built-in subagents are allowed only for sub-3-minute read-only scouting whose result feeds the commander itself. Beware ambiguous phrasing like "or a claude seat" — a harness-native commander reads any wiggle room as license for its default tools.

**Blind-panel × baseline-collision — the "what don't we know yet" analysis shape (validated 2026-07-25 on a search-performance panel).** When the deliverable is *insight from a data corpus* rather than an artifact: ① N lens analysts (disjoint lenses — technical / traffic / anomaly-hunter) read ONLY the corpus, **blind to the team's prior conclusions**, each with a mandatory「反常与惊讶」section where the value concentrates; ② the commander writes a KNOWN-BASELINE doc (what the team already knows/ruled) that ONLY the synthesis seat may read; ③ a synthesis seat collides analyst reports with the baseline and grades every candidate NOVEL / NEEDS-VERIFICATION / KNOWN / REFUTED — each NOVEL must survive an adversarial attack AND the synthesis seat re-verifying citations against the raw corpus (it caught an analyst's off-by-one on first live run). Blind analysts + informed judge is the point: feed analysts the baseline and they anchor; skip it and the judge re-reports what you already knew as discovery.

**Spec a worker by altitude + floor, not micro-rules.** The worker may do whatever it judges best so long as altitude stays right — serves the goal — with red lines and STOP gates as the only hard floor; judge on altitude, not style. Commander and critics stay bounded the other way: read-only, critique-only, propose-for-approval. Freedom is asymmetric by design — don't soften the judges; the quality lives in the tension.

Register the return contract at dispatch — the typed lifecycle card (Return channel §) is canonical; the helper lives in THIS SKILL's directory, called by absolute path: `python3 ~/.claude/skills/fleet-commander/scripts/return-channel.py register --task <id> --worker-pane <pane> --reply-to <parent> --owned-paths <paths…>` (the owned-paths conflict gate rejects a second concurrent writer at register time), and put `publish-task --result-paths …` in the job file as the worker's finish act.

**派单里的因果/范围断言是假说,不是范围 —— bake 进每份 job 契约。** 实锤 2026-07-18 同日两例:两份 PR 的第一句都在裁决派单假设、且都判它不成立——照单执行连派单自己写的复测判据都过不了。job file 必须写明:worker 第一个动作是量派单假设的爆炸半径(实测受影响面,或拿派单自己的成功判据反算),假说被证伪就带证据回报并重新定范围。自检句:**「如果我只做派单范围,派单自己写的复测会通过吗?」** commander 侧:把假设**显式**写成一句可证伪的话——没写出来的假设,worker 会当成已裁决的事实执行。
**反向同罪:契约里每条追不回上位文档的约束,是 commander 发明的假说,不是法。** 派单前把契约约束逐条对照 governing spec(实验设计/descriptor/授权文件)自身的不变量——live 2026-07-26:派单强加「100% 离线」,而实验设计原文明写对照组「同预算」且登记过「对照被做成稻草人」风险,4,100 决策全废重建。自检句:**「这条约束是 spec 说的,还是我猜的?」**猜的就写成可证伪假设并标注来源=commander。

**同族第三面:可算而不算的数字断言——它读起来像事实,所以过审时没人拦。** 2026-08-01 同日三个根不同的席位各犯一次:①commander 建议「挂真外部闹钟」,而 harness 层根本没这能力(没试过就建议);②契约断言「全部数据源超 7 天没刷新」,实际 2.58 天(一条查询就能算,没算);③报告称「数据源整体落后 3 天」,实际只有其中一张表落后 3 天、另一张只落后 14 小时(两张表由不同脚本写)。三例同形:**那个量就在手边、一条查询就能算——跳过的不是难以验证的东西,是懒得算的东西**;且三次都由平级席位拿一手证据撞出,自省零命中。上面两条防的是下游验证与约束来源,**都防不住「根本没去算」**。两句自检:**「我这句话里的数字,是算出来的还是推出来的?」**与**「说可被证伪的数字,别说模糊定性」**——『超过 7 天』能被撞,『已经很久没刷新』撞不动。

**契约的硬判据必须是 worker 手上的数据能判的,否则你要的不是执行,是猜测。** 派单前对每条硬判据问一句「**worker 拿什么证明这一条?**」:数据在别处就随单附上(或写明可取路径);取不到就把判据**降级为它能判的最强代理**并显式标注「这是代理,不是原判据」,绝不留一条 worker 无法验证却必须遵守的硬判据(2026-07-28 实锤:派单写死「入边须来自高频抓取活页」却没随单附任何抓取数据,worker 只能拿仓库内证据选源,交出的 15 个源经第三方实测**无一是活页**,换成实测高频源同量指标 16.8×,整轮返工,账在指挥不在 worker)。

**同一枚硬币的另一面:契约必须强制 worker 交出「我证不了的部分」——一份不可验证项清单,当场声明列得多不扣分。** 没有这条,worker 的自然倾向是让交付看起来完整,而**看起来完整与真正完整的交付在验收面上长得一模一样**;上例的缺陷合并前被拦下,唯一原因就是 worker 主动写了「这是仓库内证据不是抓取实测,我证不了这一点」——那句标注是契约催出来的,不是运气。

**你给 worker 定的验收标准,立刻问自己那一侧过不过 —— 定标准的人是自己标准的盲区。** 2026-07-28 同日三例、两个不同席位(要求「CI 绿才交付」自己却连推四次没查 CI、把 main 弄红;定「覆盖每一路径」自己的监测却漏掉已发生的失效模式),三次都是**自查出来的、没一次是对方抓到的**——不是能力问题,是位置问题:定标准时注意力全在对方产出上,自己那侧从未进入视野。⚠ 且每次当事人正处在对该标准**意识最强**的一刻照犯,所以动作必须是**机制,不是自觉**:**①推任何东西到共享分支后,`gh run list --commit <sha>` 锚自己 SHA 查一次 CI 再往下走**(docs-only 提交同样会挂,旁边常躺被断言的状态文件);**②凡「覆盖 N 个东西」的交付,把 N 逐条列出对表**,不靠「应该都盖到了」的感觉——覆盖完整性靠逐条对表,不靠意识到。

**批量查询脚本要内置一个已知会命中的控制样本,零命中即 ABORT。** 2026-07-28 实锤:zsh 未引号变量(`$var` 不分词,需 `${=var}`)把 15 条 URL 当成一个字符串,输出「全部 0 命中」——退出码 0、格式正常,与「这批源全废了」在观测面上完全一致;救场的是脚本预置的控制样本(一个已知会命中的 URL)同时归零。与 §4 的 `grep -c`/过滤器吞错不同源:那是**错误被吞**,这是**查询成功但查错了对象**,退出码与输出格式都发现不了。

**Independent-review contracts carry a standing attack-vector list** — proven vectors recur across unrelated codebases, so every paid/high-stakes review job cites them explicitly (a reviewer told "attack it" rediscovers maybe half):
- **bool-as-int**: any JSON value crossing a numeric gate must be type-checked — `Number(true)`→`1` silently passes finite-cost/metric guards (two live hits in 24h on unrelated parsers, 2026-07-22 and 2026-07-23). Red test: boolean input must land fail-closed, not be laundered by coercion.
- **accumulated-row-as-unit-price**: a logged cost row that sums prior stages is not a unit bound (07-23: `$0.024` "ceiling" was accumulated). Demand provenance for every claimed bound; no provider guarantee → force cap-driven derivation.
- **unguarded exit path**: the cap/limit check on the success path must exist on EVERY path — error/terminal branches that journal-and-continue cross hard ceilings (07-23: terminal `$1.70` pushed ledger past a `$1.75` cap). Red test per exit path.
- **verdict word anchoring**: `NOT APPROVED` contains `APPROVED` (see §4) — applies to any grep-based gate on enumerated words.

**Multi-round review loops need a commander-owned ACCEPTANCE BOUNDARY — reviewers ratchet.** A good adversarial reviewer expands the acceptance perimeter every round (each fix adds surface that can itself drift), so an ungoverned fix→review loop is asymptotic: live 2026-07-26, R1–R5 cleared the data plane entirely yet R5–R6 kept raising the bar on the report's self-description. The commander — not the reviewer — owns the bar: when findings stop touching the artifact the seal actually binds, issue a written boundary adjudication (what IS the sealed truth surface; which demands exceed the gate), record it IN the package, and give the reviewer an explicit **DISSENT channel** ("if this boundary endangers validity, say so in DISSENT — verdict still judged per boundary"). Corollary for experiments: hold both arms to the SAME review standard — a reviewer-invented standard applied to one arm only is itself a fairness bug.

**The completion signal is the ARTIFACT landing in the agreed directory. `return` is an optimization, never the gate.** Placement-strength patches were measured insufficient: the return command was moved to the TOP of the deliverables section, marked "not executed = job incomplete", pre-annotated that the envelope alone counts — and the very next job still came back with **zero envelope** (the sixth recurrence on 2026-07-24; the seventh the same week). Seven recurrences is a design smell: **delivery and signalling are two acts, so one can be skipped.** Fuse them with three contract clauses:
- **The output path is an INTERFACE, not a suggestion.** Write the absolute path in the contract, verbatim: **「这个路径是接口,不是建议——改名 = 交付失败。」** A worker renames to something more descriptive (2026-07-24: contract said `out/REPORT.md`, worker wrote a long descriptive name — content was excellent); a soft deviation for the worker, a **hard dependency for every downstream check**.
- **Publish ATOMICALLY — draft in `out/.staging/`, `mv` into `out/` as the final act.** A rename inside one filesystem is atomic, so the file's *appearance* in the watched directory means *complete*, never half-written — this is what makes the chunked-write rule safe to watch (chunks accumulate in staging where no watcher looks). The Done-when item is 「`out/<name>` 存在」, not "the report is written".
- **The verdict lives IN the artifact, at a fixed spot.** If the job produces a judgement (review, audit, go/no-go), the contract fixes its first line as `VERDICT: <approved|changes_requested|informational>` — one line, word-anchored, machine-readable. Skip this and the domain verdict exists only inside an envelope you just stopped depending on.

**Derived/mirror surfaces regenerate by SCRIPT, never by hand — bake the closing order into the contract.** Any package whose report/manifest mirrors source state (hash tables, terminals, timestamps, counts) will drift the moment a fix round touches the source and the worker hand-syncs the prose (live 2026-07-26: three consecutive review rounds each caught a fresh hand-edited mirror gone stale). The contract names a regeneration script and a fixed closing sequence (edit sources → regenerate derived → self-checks → package manifest); a hand-written current-state number in a derived surface = the round is void.

**A browser job file MUST carry a UI map.** Any job that drives a web UI includes a "关键控件在哪" section: where the key controls live, including controls only visible after scrolling, state-color conventions, and known dead zones — or the commander walks the flow once personally before dispatching. Live cost of omitting it (2026-07-24, a live browser workflow): a worker burned $32 clicking around a video column clipped outside the viewport, and its commander wasted 40+ clicks on the same trap.

**Open every job file with an init-suppression line**: "Skip any repo Session Init / health sweep / context ritual — this job file is your whole brief; touch only what it names." Repo-level CLAUDE/AGENTS files address a default session, and a worker obeying their init ritual burns tokens and can touch prod for nothing (2026-07-23: a tmp-scoped drafting worker ssh'd prod to report health flags nobody asked for). The commander runs init once; workers inherit conclusions through the contract, never re-derive them.

**Done when:** the job file exists outside the worker's repo, the return contract is registered, and the exact pane received one harness-correct submission with Enter separate.

## 3. Prove it started

Editor text is **not** proof of submission — confirm the worker is processing this contract: tool use, an in-flight marker, the first required action. Claude Code: a large paste can sit unsubmitted; send a second `C-m` only after a real gap (an intervening tool call or several seconds) — back-to-back Enters can be swallowed together. Pi: proof is the `read` call on the exact external job file ([PI-WORKERS.md](PI-WORKERS.md)). A queued message is not consumed: confirm the worker acted on **this** job; if it landed in the wrong pane, immediately send an explicit correction naming what to ignore and the correct scope. **Done** = target worker visibly started on this job, no other pane received it.

## 4. Heartbeat from independent state

Recheck from four independent surfaces — never the UI spinner alone:

- **pane transcript** — `tmux capture-pane -p -J -t <pane> -S -200`;
- **process/session state** — pane alive, worker jsonl mtime, ctx%;
- **deliverable / extern state — THE exit condition** — the contracted output path exists (Stage 2's staging→`mv` publish makes its presence mean *complete*); prod/DB truth;
- **the return channel — an early hint, never a gate** — a `[RETURN task=… status=…]` line in your pane, plus a `pending --reply-to <self>` scan every heartbeat, not only when you suspect a miss. The pane line is lossy and the mailbox durable, but **both are legitimately empty for a job that completed perfectly** — scan anyway (an unscanned mailbox is how returns sat unacknowledged long after their work merged), just never wait on one. For any join decision prefer ledger state — `status --task <id>` / `list --parent <self>` (lease expiry surfaces as `lost`) — over pane text (typed lifecycle card, Return channel §).

Idle (Claude Code) = no in-flight marker **and** jsonl mtime static ~3 min. Pi has no jsonl — idle = spinner absent **and** footer cost readout (`↑…↓…$…`) present. Report a **delta + blocker + next action**, never "still working." Validate actual files/status — don't trust a worker's "done." Stop and release a genuinely-finished worker (outputs preserved) to cut concurrency.

**A watch loop that only scans the mailbox watches nothing** — workers finish, print their report, and stop without running `return` (four times in one day, 2026-07-19/20; seven by 2026-07-25). Any unattended wait is TWO-condition: ① the **artifact leg** — every contracted path exists (asserted per path, not as a directory count — below); ② for each registered task with **neither artifact nor envelope**, if its pane is **confirmed idle and not `waiting`**, auto-nudge once — one line: *"if <task> is done, publish it to `<exact path>` now (and run your return command if you still can); if still working, ignore this."* Nudging about the **artifact** also recovers what the old nudge could not: a worker that finished but left it in staging, or only in its pane. **The nudge gate is two checks:** busy shape absent AND the capture shows no interactive dialog (permission prompts render as question + numbered options, `y/n`); unclear → read the capture yourself, don't nudge — a nudge into a dialog lands as a blind answer. Over-nudging is not free: Claude Code queues it, Pi delivers it as steering at the next tool boundary. A watcher's exit condition keys on deliverables/envelopes **on disk**, never `pending` count — acks drain pending mid-run (live 2026-07-22).

**Sentinel legs must be scoped to the task's delivery state, and "envelope exists" is not "envelope is new."** Two false alarms from one afternoon (2026-07-26): ① a two-seat sentinel treated ANY seat disappearing as fatal and died when a **delivered-and-acked** task's seat retired — retirement of a finished seat is expected; only a seat still OWING deliverables going away is an incident. ② `ack` records acknowledgement but leaves `return.json` in place, so an existence-based envelope leg re-fires forever after the first ack — anchor the leg on **mtime newer than the dispatch/ack baseline** (re-`register` also clears stale envelopes). And when your own acceptance check reds against a worker's green self-check, **falsify your checker first**: rerun the reviewer's exact repro command, re-derive the format (a 4-column table broke a 3-column regex), and hash the object the spec names (canonicalized payload ≠ file bytes) — two same-day false reds nearly bounced correct work.

**A sentinel you have not seen fire is not monitoring — it is a placebo.** Its silence and "all normal" are observationally identical, so an unverified watcher fails in exactly the direction that reads as *worker still busy*. Two hard rules, both from one 2026-07-24 run where a sentinel ran nine minutes with **all three legs dead** and the owner had to say the worker was done:
- **Feed it a known positive BEFORE it goes on duty** — `touch` a fake artifact, drop a dummy envelope — and confirm it actually trips. The failed leg was `ENV=$(ls <mailbox> | grep -c return || echo 0)`: under zsh `grep -c` **exits non-zero on no-match**, so `|| echo 0` appends a second `0` and `[ "$ENV" -gt 0 ]` throws `integer expression expected` every cycle. **`grep -c … || echo 0` is a banned idiom** — count with `| wc -l` or branch on `if grep -q`. The same family bites the commander's own one-off verification commands, not just sentinel scripts: `cmd 2>&1 | grep -E '<期望的成功行>'` discards the command's error entirely, so failure and success look identical (2026-07-26 two cases same day: openrsync failing on a GNU-only flag was swallowed by the grep and an empty dir nearly reported as a snapshot; a `git … | grep … | sed … || echo "✓ 无"` where `||` bound to `sed` printed nothing on zero matches). Rule: **judge whether an action succeeded by exit code and raw output ONLY; filters are for post-hoc extraction, never for pass/fail.**
- **The artifact leg asserts EVERY contracted path, one at a time (`[ -f A ] && [ -f B ]`) — never "the agreed directory is non-empty".** The loose form fails in the direction that reads as success: a multi-output contract publishes files one at a time, so the FIRST arrival makes the directory non-empty while the deliverable that matters is still unwritten (live 2026-07-26: a seat owing `REPORT.md` + `board-patch.md` published the patch first, the watcher fired ALL-DONE, and the report landed after the watch exited). The ledger join `status --task` reads `published` only after publish-task verified the whole registered set exists [enforced:H2/H3] — prefer it; the per-path shell assertion stays the pre-publish / legacy fallback. A worker may still publish out of order, so name ONE completion artifact and publish it last.
- **Write the sentinel for the shell it will ACTUALLY run under.** Harness monitor facilities eval scripts under **zsh**, where `status` is a read-only special variable — `status=$(…)` kills the script on its first assignment (live 2026-07-24: a five-leg sentinel died instantly with `read-only variable: status`). Name it `st`/`state`. The known-positive feed catches this for free **only if the feed runs under the same shell as duty**.

**Envelope is a bonus signal, never the exit — on every fabric, not just herdr.** herdr seats have no tmux notify wire at all, so there the leg is documented-unreliable *and* stacked on a worker behaviour that recurs (the seventh recurrence was measured 2026-07-24 — the worker skipped `return` even with the command as the contract's FIRST deliverable item). The tmux fabric merely hides the same failure better. Stage 2 makes the artifact itself the signal; **a watcher that still gates on `return` has re-introduced the dependency the contract removed.** **A commander seated in an agent harness arms unattended waits through the harness's native monitor facility, not detached background sleep-loops** — the harness reaps orphan background loops silently, and the kill notification is not an exit-condition fire (live 2026-07-24: two armed sentinels killed mid-watch back-to-back; the third via the harness monitor survived). Exit = **every contracted output path exists**; under Stage 2's atomic publish that is sufficient for a single-artifact job. Keep the second leg (**hook state non-`working` for N consecutive debounced reads**) when the contract has multiple outputs or when you could not impose staging. **Match the in-flight SHAPE, not a keyword** — a live turn renders `✳ Verbing… (2m 6s · ↓ 5.4k tokens)`. Same for VERDICT: `NOT APPROVED` contains `APPROVED` — a watcher grepping `APPROVED` reported approval for a rejection (live 2026-07-22); anchor words (`grep -E '(^|[^A-Z])APPROVED'` plus an explicit `NOT[ _-]?APPROVED` negative check), and act only on the RETURN file itself.

```bash
tmux capture-pane -p -t "$pane" -S -25 | grep -qE '…\s*\([0-9]+[ms][^)]*↓[^)]*tokens\)'
```

This shape is **Claude Code only** — busy Pi renders a braille spinner `⠼ Working...`, read as idle by this regex. Pick the shape by harness BEFORE scripting the watch; for Pi use [PI-WORKERS.md](PI-WORKERS.md) § Heartbeat and context. A no-match on a seat you know is busy-capable is "unknown", not "idle" — capture and eyeball before any nudge. **A sentinel/wait LOOP must DEBOUNCE the idle verdict — one `capture` between two tool calls catches a transition frame where the busy shape is momentarily absent and ends the wait early** (live 2026-07-24: a sentinel woke at ~20s on a worker still mid-task). Require **N consecutive** non-busy reads (3 worked) over a wider window (`-S -8`), count `Calling`/`Called`/`…` as in-flight; the artifact/ledger leg stays the trusted exit, debounced-idle is only a scheduling hint.

**Your own contract clauses can defeat your watcher's heuristic — check the two against each other before arming.** Stage 2 mandates **chunked writes (≤80 lines per append)**, which produce **plateaus** in output-file size between chunks. A watcher whose completion leg is "file size unchanged for N cycles" reads those plateaus as done (live 2026-07-25: a 3×30s size-stability leg declared ALL-DONE on a worker still 8KB from finished — the two rules were written by the same commander an hour apart). Stage 2's staging→`mv` publish dissolves *this* instance, but the duty survives it: **a size-stability leg is only valid ANDed with a harness state read** (`agent_status != working`) **and given a window wider than the worker's slowest chunk gap.** Generalize: after writing any watcher, re-read your own job contract and ask *"which clause here produces a signal my watcher will misread?"* — output-cadence rules (chunking, staged commits, batch sleeps) are the usual culprits. Keyword markers measured false on a live 12-seat fleet (2026-07-20): `esc to interrupt` renders in zero worker panes; bare `tokens` matches idle hints and completion summaries; neither is a reliable liveness marker.

Two states must not be collapsed into busy/idle: **`waiting`** (parked on an interactive dialog — blocked on a human tap, the highest-value signal) and **`agents`** (prompt idle, background agent still turning); both read "idle" under a two-state model. Never nudge a `waiting` seat — answer its dialog. One nudge per task per watch; if the envelope still doesn't appear, escalate to the full four-surface recheck — if that's empty too, surface the seat as blocked. Never re-nudge.

**Anomaly duty — the watcher's one real safety job:** independently sanity-check whatever sits on the revenue / prod / irreversible path (CTA wiring, deploys, DB writes); if a worker is about to cross that line with a failing gate or mis-fix, STOP it and alert the user BEFORE the point of no return.

**ctx-probe — long-context degradation measurement (owner ruling 2026-07-31: ride on daily traffic, never burn quota on a dedicated run).** Piggyback on any broadcast/steer/heartbeat to a seat: append three control questions whose answers MUST be in the seat's own context (session name, model+effort, SEAT.md path). Score 0-3 strictly; record `{"seat","model","ctx_pct","score","answers","correct"}` to a readings log inside the concern's own workspace (`~/fleet/<concern>/ctx-probe/readings.jsonl`), with a small probe/score script pair beside it. The probe is ONE message, not a conversation — ask, capture the JSON, score, move on. Accumulate readings across natural ctx% variation; once ≥20 data points exist per model, bucket by ctx% and plot the degradation curve. The curve answers "at what ctx% does this model start forgetting its own identity" — that's the compact trigger line. First-round baseline (2026-07-31, 13 seats): 7/13 perfect at ctx 6–62%; session-name confusion is the first failure mode (a human-facing alias vs the real tmux name); the SEAT.md path question fails on seats that never built one.

A shared `ECONNRESET` across several workers is usually a transport/proxy/upstream transient — probe connectivity and watch for auto-recovery before restarting; a self-recovered long context beats a restart. Shed load by stopping finished workers, not by killing a recovering one. **Done** = state read from transcript + process + deliverable, each live worker's delta/blocker/next statable.

## 5. Correct / continue safely

Inject the next batch (Stage 2's small-correction form) once the worker is idle at a checkpoint — workers often don't self-continue. The worker chat is disposable; disk state (queues / RESUME / skip-list) is the SoT. At high context: wait for a safe checkpoint, persist to disk, reset harness-correct — Claude Code `/clear`; Pi kill + fresh relaunch off the disk SoT (`/compact` is the in-flight-only rescue, PI-WORKERS § Context economy) — and re-inject the launch pointer.

A rebase/checkout dying with `could not detach HEAD` is an untracked collision until proven otherwise — an untracked file squats a path the incoming commits now track. Diagnose: `git status --porcelain | grep '^??'` ∩ `git diff --name-only HEAD..origin/main`; move or delete the stray and re-run. **Never** `reset --hard` / `clean -fd` on a shared checkout — sibling chats have uncommitted work there.

**为测试而挪开的回滚物,其恢复或清理必须发生在读到测试结果之后的下一个批次,永不与被测动作同批。** 批处理很容易把「执行动作」和「清理退路」写进同一次调用,于是在看到 rc 之前退路已经没了(2026-07-26 实锤:指挥官把一个完成标记**改名**挪开——手法正确、可逆——却在同一批命令里 `rm` 了那个改名文件;那一跑恰好失败,当日产物被留在半成品态,已无标记可还原)。改名保留是对的,同批清理把它作废了。

Outward or irreversible actions (publish, deploy, prod write) need the user's **current-session** explicit go — and where merging auto-deploys, the merge itself IS the deploy: gate it as such. Before retrying, verify present external state — a redirect is not proof. **Dedupe before retry** (Guardrails): e.g. after a social-media platform `/upload`→`/content`, verify via unique-caption search + known-positive control + drafts/count/status before reposting. Record the final external status / URL / timestamp in the task artifact. **Done** = outward action authorized this session, confirmed against real external state, result recorded.

**等待/验证 CI・deploy 时锚自己的 merge SHA,不锚「分支最新」;落地判据 = prod HEAD == 你的 merge SHA(或平台的 deployed-revision 标识)。** `gh run list --branch main --limit 1` 取到的是**那一刻**的最新 run;连环合并时它极可能属于**上一个** merge(2026-07-18 实锤:一次查询取到了前一笔 merge 的绿,prod HEAD 也仍在前一笔)。正确姿势:`gh run list --commit <merge-sha>`。派 worker 验证同理:给 SHA、令回执回显它实际所在的 SHA,逐字相同才算数。

**merge 命令裸跑,永不接管道;成功判据 = `mergeCommit` 非空。** `gh pr merge … | tail -1` 把失败退出码洗成 tail 的 0,`&&` 链照走(2026-07-19 实锤:draft PR 被拒,ack 与 watcher 照跑,watcher 拿空 SHA 空转)。draft 先 `gh pr ready`;merge 后立刻断言 `mergeCommit` 非空,空 = 没合上,别往下走。

**等待循环必须两段:先证 X 存在,再证 X 终态——「未完成数==0」在空集上恒真。** merge 后 run 创建有数秒延迟,锚 commit 查询在其诞生前返回**空集**——循环直接穿过,读到的「成功 + prod HEAD」全是上一笔的(2026-07-19 实锤)。推广:任何「等 X 完成」的轮询,若 X 由本次动作异步创建,先证存在、再证终态。

## 5b. Context management — 舰队比任何单个 context 都长寿

**Worker 侧。** 任务间无需决策:每个新 task_id 前按 harness 正确机制重置(Stage 2),不设百分比阈值;ctx% 只在 in-flight 中途有意义——逼顶走 Stage 5 落盘重启。清/杀前三件:idle、无未 ack 的 pending return、交付物已入 SoT。永不清 in-flight 的 worker;transient 网络错后恢复中的长 context 优先等待(Stage 4)。

**Commander 侧。** 对话锚是下条「磁盘交接书」的**补充**,不是主机制(4.15.0 起 SoT 在 `~/fleet/<concern>/SEAT.md`)。`/compact` 前先在对话里写「压缩生存锚」(锚本体写对话——摘要会带上它):目标与完成判据、在飞单(task_id + 分支)、验收纪律链、现役哨 id、醒来第一动作。标准:**压缩后的你零记忆也能只凭它续航**(2026-07-18 两次实操无损)。compact 是队列命令:send-keys 到自己 pane,本轮话说完再压,时机选回执间隙。ctx 60% 不是恐慌线;红线是「处理大单验收时才发现不够」。

**常驻席磁盘交接书(标准条款 2026-07-30,owner 普及令)。** 每个常驻 cmdr 席维护 `~/fleet/<concern>/SEAT.md`(git 管),标准=「零记忆的下一个模型读完就能接着干」。对话锚是补充,交接书才是 SoT——摘要整体不可靠,丢 skill 只是特例,**席位身份同样会被压掉**;检测(`Skills restored` 行)会漏,冗余不会。三条硬要求:压缩**前**同步更新;压缩**后**第一动作读它;内里一切易变 id(pane/workspace/task_id/旗标)标注「用前重新 list」。具体协议应与该 concern 的 `SEAT.md` 一同版本化。

**时钟型承诺不能只写进锚——压缩后没人叫醒你。** 锚只保证醒来后知道做什么,不保证按时醒来:任何「到点必做」(验收窗、派单点、测量点)在 compact/静默前必须挂**外部闹钟**(harness 的 cron/scheduled-wake 设施,或明确请 owner 到点唤人);二者都没有就把「迟到多久可接受」写进锚,醒来第一动作先对时并如实报迟(live 2026-07-24:19:20 canary 派单点因 compact 后无外部唤醒,23:10 才补派,迟 3h50m——锚写得再全也追不回时钟)。

**Session 生命周期 —— tmux session 是弹性资源,不是固定编制。** concern 真正结束(交付已验收入 SoT、无后续单、无 pending return)的 session 就 kill(kill 前 capture 最后一屏留档);新 concern 就创造(`tmux new -d -s <name>` → yolo 启动 → 等真 prompt → cd 进驻 worktree)。舰队规模跟活走——空转 session 是负债(statusline 噪音 + 误投递面 + 幽灵 ctx)。边界:只 kill 自己创建或 owner 点名的 session(Stage 6);同 concern 还有后续单用 `/clear` 保 session,concern 终结才 kill。

## 6. Verify handback and clean up

Completion = required outputs exist **at their contracted paths**, validations ran, and external state is unambiguous — verify each yourself against the actual result. A **return** envelope, when present, is a convenience: read its verdict early, then `ack` it — but grade the artifact, never the envelope's word. When absent, completion is still completion: grade the artifact, take the verdict from its fixed first line (Stage 2), and close with no ack to give. Then propagate one normalized return upward (topology and root case: Return channel §).

**Checklist line 1 is identity, not content: "is this the artifact I dispatched?"** For a PR, `gh pr view <n> --json headRefName,state` must match the branch the job file named; for a file, the path must be the one you owned to the worker. A mismatch is **not** an automatic reject — a re-cut or renamed branch can still be the right work — but must be **explained before content is graded**: a green gate on the wrong head proves nothing about the worker you dispatched (once skipped: merged a stale-shared-branch PR; the real worker's clean branch was closed as duplicate).

**Identity has a second half — the right branch AND a current one — and `git diff origin/main..HEAD` is the wrong instrument.** A worker branch cut at yesterday's main renders every commit main gained since as a **deletion** in that diff, so a fast-forward merge silently reverts them; the commits most at risk are the commander's own, still being written to main while the worker works. Live 2026-07-26: a four-file rewrite came back clean and self-checked, but its branch predated the commander's own measurement commit, so the diff listed a board file and two data files as removed. **Grade the worker's actual change set with `git show --stat <worker-commit>`; use the base diff only after `git fetch && git rebase origin/main` has made the two agree.** A worker's honest self-report cannot catch this — the drift is on your side of the fence.

**证据必须真的走过它声称的那条路径 —— 「跑了第二次,rc=0」可以字面为真、实质为空。** 2026-07-26 实锤:一份归档脚本的验收要求「再跑一次证明增量生效」,worker 照做并给出漂亮数字,但那一跑命中了脚本自己的当日完成标记早退分支(日志白纸黑字 `result=already_complete`),真正的重复拷贝路径一次都没执行过;指挥官把标记挪开真跑立刻 rc=1。两条义务:①派单要求「跑两次证明幂等」必须写明**第二次要走真实路径,不得命中短路/守卫/缓存**;②验收自证报告时不只读结论,要问**这份证据执行的是不是它声称的那条分支**——短路的证据就躺在 worker 自己贴出来的日志里。

**Failing tests are adjudicated against base FIRST.** Before attributing a failure to the worker, rerun it on the PR's base/main (2026-07-22: worker self-reported 25/25 green; independent rerun found 3 failures — all reproduced on pristine main, baseline debt). Verify the counting scope of any self-reported pass count — it may cover a subset.

Stop/close only sessions **you** created or the user explicitly names; leave unrelated sessions running. After launch, hand the user the exact monitor commands (`tmux attach -t <concern>`, `capture-pane -p -J -t <pane> -S -200`). On any surprise or correction, follow [HARVEST.md](HARVEST.md) at the next safe checkpoint — harvest during the run, not from memory at the end. Keep one methodology owner on skill files so implementation workers never race that surface.

**Skill-extraction duty (owner ruling 2026-07-24): when the work itself reveals a reusable asset, the commander proposes the skill — the user should never have to.** The tell: the same class of knowledge got earned more than once in a run, or it would obviously outlive this project and can't be trusted to project memory. At the next safe checkpoint ask one concrete question — "这类 X 要不要建个专门的 skill?" with a one-line scope sketch — then on approval run it as a normal dispatch (worker drafts from first-hand evidence, commander reviews/commits). Live case: five external-API wire fixes in one day became a dedicated integration skill, owner-prompted; this duty exists so next time it isn't.

## Return channel — Worker → immediate parent (an intermediate commander, if any) → Mastermind

Left→right dispatch is reliable; right→left completion is not unless someone polls — so completion is anchored to the **artifact** (Stage 2) and this channel rides on top, carrying the verdict *earlier* than a file read. Every dispatched job still registers and names a **return** to the exact runtime `reply_to` (keep it in the contract under "nice to have", never Done-when); it gates nothing — a worker that ships the artifact and skips it has SUCCEEDED, and §4 already treats it that way. Topology is live state: inventory it per task, never infer the parent from a familiar pane name. A real hierarchy returns one hop to the immediate parent, which verifies and propagates one normalized return upward, **minting a NEW task_id per hop** (never re-register the inbound id upward — the upsert would clobber the worker's contract). **Mastermind** = the topmost seat the user talks to; its ack authority is the user's rulings, not its own. Root case: this commander IS the top — the chain terminates with ack + a report to the user, no upward `return`.

**Typed lifecycle — ONE canonical card.** Mechanics live in `scripts/return-channel.py` (durable mailbox outside any repo; atomic temp-write+rename envelope; pane validation; safe notify; mailbox-level lock in v2.0.0). Nine verbs; **every CLI option, the four enum vocabularies, and the state-machine diagram live in `--help` — kept truthful by tests, so read it, never restate it here.** The lifecycle a job runs, in order:

`register --owned-paths` (conflict gate — overlap, equal or ancestor/descendant, with any ACTIVE non-acked/aborted task's owned_paths → registration REJECTED naming the conflict, zero side effects; serialize or stack instead) → `dispatched` + `heartbeat --lease-seconds` (an expired lease flips `dispatched|started` → `lost` on the QUERY side only; `lost` still HOLDS its owned_paths until a human `abort` — `lost→acked` is illegal, the only exits are re-dispatch or abort) → worker `started` → staging→`mv` → **`publish-task --result-paths`** (the single atomic finish act: verifies ALL paths exist → sha256 → commits the `published` ledger snapshot → wakes parent; any missing path = zero side effects even for a lease-expired task; the set must equal the REGISTERED result set, set-equality after canonicalization [enforced:H2] — the worker cannot swap deliverables; `published` is reachable ONLY here, never via `transition` [enforced:H3]) → commander verifies the real artifact → `transition --to verified` → `acked`. **A join reads `status`/`list` (ledger state), never "directory non-empty" or pane text.**

**A live parent gets the wake leg — do not put `--no-notify` in an ordinary worker job.** `publish-task` has two intentionally separate effects: durable `published` truth and a best-effort parent wake. `--no-notify` suppresses the second. It is legal only when the commander has deliberately installed a separate ledger joiner that will detect publication; a vague intention to check later is not one. Otherwise a worker can finish, publish, and sit idle while the commander keeps calling it active (2026-08-04: a herdr worker published its result set and went idle; the `--no-notify` baked into its job file hid the completion until the user noticed). Durable truth prevents loss, not delay.

**Traps that outlive the mechanism — keep them in the body, `--help` cannot show them:**
- **`task_id` byte-for-byte identical** in `register` and in the job file's return/publish command — a case mismatch (`url-audit-a` vs `url-audit-A`) survives on APFS only; on any case-sensitive volume the envelope writes to an unregistered id, the parent's `pending` never sees it, the return is silently lost (2026-07-25, caught by luck not a check). Generate the id once, paste into both; a case-sensitive watcher `grep` fails the same way.
- **register is an upsert** keyed by `task_id`: re-run with a new `--worker-pane` to re-point the contract, no dedupe, nothing downstream changes; a bare register stays v1-byte-identical and writes no ledger, while a register over an existing ledger opens a new attempt/generation.
- **A re-return revokes the earlier ack** — a worker returning again on the same `task_id` (the revise loop) sends the envelope back to `pending` so a sentry sees it (before 2026-07-18 a re-return after `ack --decision revise` was invisible to `pending`, and a missed wire line would sleep forever). And `ack` rides in the SAME batch as the disposition it acts on — a deferred ack is one the sweep finds weeks later.
- **v1 and typed are two lanes:** `publish-task` does not write `return.json`; v1 `ack` requires it and does not advance the ledger. A migration-era commander receiving a v1 envelope still owes mtime-anchoring + same-batch ack + the re-return rule; don't assume every task is typed, and v1 `register`/`return`/`ack` remain legal.
- **help is a PULL surface, not a push** — its truth reaches only a session that runs it, so the non-obvious state changes above stay in this body. `status`/`outcome`/`decision`/`state` are FOUR never-conflated vocabularies (a review wanting edits is `status=done outcome=changes_requested`, never `status=CHANGES_REQUESTED`); the wire carries enumerated fields + a pointer, worker prose lives only in the envelope.
- **queries are not pure reads** — `status`/`list`/`transition` apply lease expiry (write `lost`) and lazily migrate legacy tasks; script watchers as side-effecting.

**Worker 的非 return 上行(纠错/情报/更正)必须以 `[FROM <pane>]` 前缀开头** —— 裸文本上行读起来像「不知道谁发来的消息」(2026-07-19 一条裸文本纠错让用户误以为消息串错了窗口);且与一切约定一样,**必须 bake 进 job file 才会存在于 worker 侧**。

**要求回执的跨席指令必须内嵌回执命令本身 —— 约定不随消息走,机制才随消息走。** `[FROM]` 与 return-channel 是本 skill 的约定,只存在于载入了它的席位;对方指挥席可能从未载入、`/clear` 后必然丢失(2026-07-21 实锤:请另一指挥席回一行确认,对方把回执写在自己 pane 当聊天输出,通道从未打通)。把回执命令逐字写进指令行。

**跨席消息的「已送达」判据是对方的输入行为空,不是「capture 里看得见我发的字」。** `capture-pane` 会把输入框内容一并抓出——未提交的长消息读起来与已进 transcript 的一模一样(2026-07-26 实锤:发完 `send-keys -l` + 单独 `C-m` 后 capture 到全文判「已消费」,实际那段话在对方输入框躺了十几分钟)。正判据两条同时成立:`❯` 那行**是空的**,且消息出现在输入框上方的 transcript 区;补 `C-m` 前先隔一个真实间隔——连发两个 Enter 会被一起吞掉。

## Fleet-loss recovery (server death, reboot, tmp cleanup)

The default mailbox lives under a tmp-class path, while job files/contracts live in durable `~/fleet/<concern>/jobs/` — the recovery SoT (do NOT treat both as lost together). The whole tmux topology lives in one server — a reboot, tmp cleaner, or tmux crash voids every contract's panes at once, and pane indices renumber even on routine kills. Drill: ① census survivors **per harness** — `tmux ls` AND `herdr workspace list`; a herdr fleet does not live in the tmux server and survives its death intact (2026-07-23: tmux socket+server gone, all herdr seats + mailbox unaffected; the durable envelope carried the in-flight return). Does the mailbox dir still exist?; ② relaunch seats (Stage 2 recipes); ③ re-register every open task from its job file — register is an upsert, job files are the surviving SoT (if tmp died too, re-author from the boards); ④ one line per open task: contract restored, re-run your return. After ANY pane kill/recreate or relayout, re-register open contracts against the re-inventoried topology — a stored `reply_to` is a snapshot, not a live pointer.

## Remote workers over ssh

A worker on another machine (24/7 Windows box, cloud host) fits the same loop with two substitutions: its pane runs `ssh <host>`, and the watch surface becomes **handback + machine state read over ssh** — the files/configs it wrote and the actual effect (does the thing now work?), never its narration; its transcript lives in remote `~/.claude`, unreachable. Verify self-reported facts by reading the machine (2026-06-17: a claimed pubkey was `cat`-read on the box and fingerprint-matched before prod authorization). A remote worker blocked on an authority it lacks (prod key, secret) stops and hands back — the commander often holds that authority: execute the gated step yourself after explicit user approval, least-privilege. Its memory is the remote machine's, useless to the main line — harvest into the canonical skillbook yourself.

## Guardrails (the three true hard rules — everything above is a positive recipe)

1. **Harness-correct, serial delivery** (§2): one unique named buffer per Claude Code job — the unnamed global buffer races across panes; Pi gets one literal-line pointer, never the multiline body; deliver to panes serially.
2. **Dedupe before any outward retry** (§5): a possibly half-succeeded action (publish / deploy / post) is verified against present external state — a unique-key search plus a known-positive control — before a second attempt; a redirect or a queued message is never proof it landed.
3. **agent-view is not the chat editor, and the daemon is shared.** The agent-view input box has different key semantics (**enter = return, space = reply, ctrl+x = delete**): each blind Enter can hatch a *new* background daemon session while the UI looks unsubmitted (once mis-hatched 3 ghost sessions; one opened a duplicate PR). So: before appending a message, **confirm the pane is in chat view**; for a parallel session, spin your own `tmux new -d -s <concern>` rather than poking agent-view; **after any agent-view interaction, census what actually spawned**. Ghosts live in the shared claude daemon — a dead TUI does not kill them; **point-kill** by the pid whose `--session-id` / `--resume <jsonl>` matches, never the daemon tree. Treat this daemon/session distinction as structural, not cosmetic.
